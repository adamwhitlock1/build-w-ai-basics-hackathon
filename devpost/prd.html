Porchlight

A per-family-member homepage where every widget is AI-driven — pre-built ones are auto-curated from each member's interests, and any member can describe a new widget in plain language and have it built and rendered. Built for the learner's own household first; market is later.

Screens and Layout

One main surface, a few small ones around it

Porchlight is mostly one screen — the homepage. The rest are entry/exit ramps and an inline prompt.

Login / Sign-up
Email + password, a "create account" toggle. Invite links go to "set your password" then straight to the homepage.
Create-Family Intro
Form fields: family name, co-admin emails, the parent's interests (freeform), the parent's location (freeform). One "Create family" button.
The Homepage ★
Sidebar (member list, invite) + main 4-column grid (seeded widgets, empty slots, "+" icon). Switch view from sidebar swaps the data behind it.
The New-Widget Prompt
Inline expansion at the top of the grid. Single text field with example placeholders, "thinking" state, success → widget animates in.

Features and Behavior

What each piece does, with checkable acceptance criteria

Authentication and Account

Email + password for everyone. New accounts via sign-up or invite link. Each account belongs to one family.

  • A new sign-up lands on the create-family intro.
  • An invitee clicking the invite link lands on "set your password," then on their own homepage.
  • Logging in with valid credentials takes the user to their own homepage; invalid credentials show an inline error and the form stays put.

Family Management

The family is the unit. Admins can invite members and switch to any member's view. Non-admins can only see their own.

  • The create-family form saves and the family is queryable.
  • The sidebar lists all family members; clicking a member's name swaps the homepage contents to that member's data.
  • An admin can invite a new member from the sidebar; the invitee receives a working link.

Articles Widget (pre-built, AI-curated)

A card listing 3–5 article summaries — title, one-line summary, source. LLM crafts search queries from the member's interests, fetches via Brave Search.

  • The widget shows 3–5 items, each with a title and a one-line summary.
  • Items are relevant to the member's interests (a member whose interests are "space exploration, soccer" sees articles about space and soccer, not random topics).
  • A "refresh" control on the card re-fetches and updates the list.

Local Events Widget (pre-built, AI-curated)

A card listing 3–5 upcoming local events — name, date, venue, one-line description. LLM uses interests + the member's location.

  • The widget shows 3–5 events, each with a name, date, and venue.
  • Events are local (anchored to the member's location) and relevant to their interests.
  • A "refresh" control re-fetches and updates the list.

Custom Widgets ("Describe-a-Widget") The Kernel

Anyone clicks "+", types a sentence, sees a thinking state, and a new widget appears, populated with live data.

  • Clicking "+" opens the prompt.
  • Typing "show me upcoming SpaceX launches" and submitting produces a widget titled roughly "SpaceX Launches" containing a list of upcoming launches.
  • During the LLM/API call, the prompt shows a "thinking" state (no submit, no escape).
  • On success, the new widget is in the grid, draggable, and persists across page reloads.
  • On failure, an inline "Try again" button appears; clicking it resubmits the same prompt.

Drag-and-Drop Layout

Reorder and resize (1/4 → 4/4). Auto-saves on drop. Each member's layout is independent.

  • Dragging a widget into a new position moves it; releasing the mouse drops it there.
  • Resizing snaps to 1/4 increments and persists.
  • Logging out and back in preserves the layout.
  • Switching to a different family member's view shows that member's layout, not the admin's.

Data Sources

A small, named menu: news_search, events_search, web_search. v1 ships one backing service: Brave Search. The LLM picks one by name; a registry maps names to handlers.

  • The LLM's output for a custom widget specifies one of news_search, events_search, or web_search.
  • The system successfully calls Brave Search for the chosen source and renders the result.

States and Boundaries

What the user sees in each situation

First use
Two pre-seeded widgets + 1–2 empty placeholder cards. "+" always available.
Logged out
Any page except /login redirects to /login. Invite links work for logged-out users.
LLM / API failure
Inline "Try again" button on the prompt; clicking resubmits. No widget is added.
No matching content
"Nothing new today — try refreshing later" instead of empty space.
Duplicate invite
Sidebar surfaces "Already a member" and does not send a duplicate.
Persists
Interests, location, layout, custom-widget definitions, last refresh of pre-built widgets.
Permissions
Admins edit any member; non-admins edit only their own. Everyone can rearrange and create on their own page.
Does not persist
Pre-built widget results — re-fetched (and re-LLM'd) on every page load or refresh.
